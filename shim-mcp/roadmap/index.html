Shim MCP roadmap

What's being fixed and built next for Shim MCP, the open-source WordPress MCP server. Every item is a GitHub issue you can follow, vote on with a comment, or pick up yourself.

By Aditya Raj Singh · Updated 22 October 2026

Current release: 1.1.0, out on WordPress.org and GitHub since 22 October 2026. 18 items are planned. The status on each item comes live from GitHub, so it changes the moment an issue closes. There are no dates. Fixes come first, and the rest moves up when people ask for it.

Fixing first

  • #49

    Work alongside the official MCP Adapter

    Planned

    When the MCP Adapter plugin is also loaded, for example because another plugin bundles it, Shim's server lists no tools. Shim will register its tools at the right moment and keep the two servers apart.

  • #50

    Respect abilities that opt out of MCP

    Planned

    Plugins can mark an ability as not meant for MCP. Shim will stop exposing those, and keep picking up abilities that don't say either way.

  • #51

    Check the Origin header

    Planned

    The HTTP transport will refuse requests from unexpected web origins, as the MCP spec requires, to block DNS rebinding attacks.

Connections

  • #54

    Connect from claude.ai and ChatGPT

    Planned

    An OAuth 2.1 sign-in, so web connectors can add your site by its URL and you approve them in wp-admin. Application passwords keep working.

    Help wanted
  • #52

    Newer MCP versions

    Planned

    Support for the 2025-11-25 and 2026-07-28 versions of the protocol, next to the three Shim speaks today.

    Help wanted
  • #64

    More clients and a better connection test

    Planned

    Ready-made setup for VS Code, Windsurf and Codex CLI, and a test that says exactly why a connection fails, such as a host stripping the Authorization header.

Control and safety

  • #55

    Choose which abilities clients can use

    Planned

    Switch abilities on and off in Tools > Shim MCP, plus a read-only mode for assistants that should look but not touch.

  • #56

    Confirm before destructive actions

    Planned

    Deletes and other destructive actions wait for a person to approve them, in the AI client or in wp-admin.

  • #57

    Activity log

    Planned

    A record in wp-admin of every call a client made: who, what, when and whether it worked, with secrets left out. Nothing leaves your site.

  • #66

    Undo

    Planned

    Each change made over MCP gets an ID you can undo from the client or from wp-admin, for posts, options, terms, menus, users and plugin settings.

    Help wanted
  • #53

    Hooks around tool calls

    Planned

    Two filters, before and after every tool call, for developers who want to log, block or reshape calls.

    Good first issue

More of WordPress

  • #58

    Media from a URL and featured images

    Planned

    Upload an image from a link instead of pasting it as base64, and set or clear a post's featured image.

    Good first issue
  • #59

    Custom fields

    Planned

    Read and write post meta, including ACF values, with WordPress's internal keys kept out of reach.

  • #60

    SEO fields

    Planned

    Titles, descriptions, canonical URLs and robots settings for Yoast SEO, Rank Math, All in One SEO and SEOPress, through one set of abilities.

    Help wanted
  • #61

    Block themes

    Planned

    Templates, template parts such as the header and footer, global styles and patterns.

    Help wanted
  • #62

    Themes and updates

    Planned

    Activate and install themes from WordPress.org, and apply plugin and theme updates.

  • #67

    WooCommerce

    Planned

    Products, orders and customers, through WooCommerce's own abilities where your version has them.

    Help wanted
  • #63

    Search in discovery

    Planned

    Filter the ability list by category or text, so clients spend less context finding the right tool.

    Good first issue

Not planned for now

  • A hosted relay or an account. Shim stays a plugin that talks only to your site.
  • Page builder editing for Elementor, Divi or Bricks. Each builder stores content its own way.
  • Running WP-CLI commands over HTTP. It widens what a client can do and overlaps with the abilities above.
  • Rate limits and IP allowlists. Your host or a security plugin does these better.
  • Shim's own MCP resources and prompts. Little demand so far.

Think one of these should be on the list? Say so on the roadmap issue.

How to help

  • Tell us what matters to you. A comment on an issue is how it moves up the list.
  • Pick up a good first issue. Send pull requests to the dev branch. The README explains how to run the tests.
  • Found a bug? Open an issue.
